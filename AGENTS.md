# Development guide

## Environment and source boundaries

- Use Node.js 24.x for local development.
- Treat `src/extension.ts` and `src/extension/` as extension-host source, and
  `src/webview/` as webview source.
- Treat `src/shared/` as the validated protocol boundary shared by the extension
  host and webview.
- Files under `assets/academic/` are generated by `npm run compile`. Never edit
  them by hand; update their source and commit the regenerated output together.
- Keep interactive fixtures in `manual-tests/` and independently invoked
  automated tests in `test/`.
- Preserve unrelated worktree changes. Do not reformat, refactor, or remove
  adjacent code unless the requested change requires it.

## Required workflow

1. Inspect `git status` and identify the exact files in scope.
2. Update the narrowest source and test surface that can express the change.
3. Run `npm run compile` when webview source changes so generated runtime files
   remain synchronized.
4. Select the required checks from the verification matrix below.
5. Review `git diff --check`, the final diff, and the worktree status before
   committing.

Do not add tests to `build`, `vscode:prepublish`, or another routine packaging
path. The automated suites must remain independently invoked.

## Verification matrix

| Change area | Required verification |
| --- | --- |
| Documentation only | Check commands, links, headings, and `git diff --check`. |
| Extension, webview, protocol, or scripts | `npm run check` and `npm test`. |
| PDF.js adapter, reader UI, citation preview, or PDF diff rendering | `npm run check`, `npm test`, and `npm run test:viewer`. |
| Provider lifecycle, command registration, or editor integration | `npm run check`, `npm test`, and `npm run test:extension`. |
| Packaging or release contents | `npx @vscode/vsce ls --tree`. |
| Vendored PDF.js update | Follow every check and manual test under **PDF.js vendoring**. |

`npm run check` performs a clean build, TypeScript checks, and ESLint. The clean
build regenerates `assets/academic/`, so review those changes rather than editing
or discarding them independently.

## Proposed API and manual acceptance

- Treat `customEditorDiffs` as version-sensitive. Test it in a compatible VS
  Code build with Proposed API access enabled for
  `ovolab-veritas.academic-pdf-viewer`.
- Press `F5` to launch the Extension Development Host. The launch configuration
  enables the proposal and opens `manual-tests/`.
- `npm run test:extension` covers activation, command registration, and ordinary
  custom-editor lifecycle; it does not replace the real Source Control diff
  workflow.
- For PDF diff changes, manually verify unstaged and staged revisions, added and
  deleted PDFs, highlight toggling, previous/next navigation, synchronized
  scrolling, reload, and closing either side.
- For reader interaction changes, manually verify navigation history,
  `Ctrl/Cmd+Wheel`, `Ctrl/Cmd+Shift+P`, link clicks, and both Control-hover input
  orders.

## PDF.js vendoring

- Runtime PDF.js files, its Worker, fonts, CMaps, and WASM assets must remain
  bundled so installed extensions work fully offline. Never load them from a
  CDN.
- `assets/pdfviewer/vendor.json` is the machine-readable version record.
- Use `npm run pdfjs:check` for a read-only query of the latest official release.
- Use `npm run pdfjs:update -- --version x.y.z` for an explicit,
  checksum-verified, staged update. Never replace `assets/pdfviewer/lib`
  manually.
- Use `npm run pdfjs:verify` for an offline vendor-layout and version check.
- Keep `assets/pdfviewer/lib/pdf.css`; it is extension-owned. The updater omits
  source maps, debugger/example assets, and the unused scripting sandbox.
- After an update, run `npm run check`, `npm test`, `npm run test:viewer`, and
  `npm run test:extension`. Manually verify normal, long, CJK, and form PDFs;
  link previews; Git diffs; changed-region highlights; and shortcut routing.

## Security boundaries

- Do not weaken the webview Content Security Policy.
- Do not re-enable PDF JavaScript evaluation or restore the unused scripting
  sandbox without an explicit security review.
- Keep webview-to-extension messages runtime-validated in `src/shared/protocol.ts`.
- Keep local and Git-backed PDF size limits in place unless a reviewed design
  replaces them.
- Do not introduce network dependencies for opening or rendering local PDFs.

## Release discipline

- Do not change the extension version, release channel, Preview designation, or
  `CHANGELOG.md` unless the task includes release preparation.
- Inspect release contents with `npx @vscode/vsce ls --tree` before packaging.
- Showcase images excluded by `.vscodeignore` must use stable GitHub-hosted URLs
  in `README.md` so they render from the packaged extension page.
- Keep source, tests, manual fixtures, repository guidance, and local test-host
  downloads excluded according to `.vscodeignore`.
- Do not add GitHub Actions unless the maintainer explicitly requests them.
